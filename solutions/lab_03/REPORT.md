## Задание 2. Циклы и базовые алгоритмические схемы
*Временная сложность:*
- вычисление суммы: $O(n)$ - линейно один раз проходимся по последовательности (n - количество элементов);
- поиск минимального значения: $O(n)$ - линейно один раз проходимся по последовательности (n - количество элементов);
- поиск максимального значения: $O(n)$ - линейно один раз проходимся по последовательности (n - количество элементов);
- подсчет четных значений:  $O(n)$ - линейно один раз проходимся по последовательности (n - количество элементов);
- подсчет значений, превосходящих среднее арифметическое: $O(2n)$ в асимптотике упрощается до $O(n)$ - дважды линейно проходимся по массиву (n - количество элементов);
- линейный поиск первого вхождения числа: $O(n)$ - линейно идем по массиву, пока не встретим искомое число (n - количество элементов, стоящих перед искомым +1; в худшем случае - длина массива);
- проверка простоты положительного целого числа: $O(n*sqrt(m))$ - запускаем цикл с $sqrt(m)$ повторениями (n - количество элементов  массива; m - проверяемое число).

Дополнительная память для каждой операции константа - O(1), т.к. добавляем только новые числовые переменные. 

Если число $n$ составное, то его можно представить как $n = a * b$, где хотя бы один из множителей не превосходит $\sqrt{n}$ — 
иначе их произведение было бы строго больше $n$, что невозможно. Следовательно, достаточно перебирать делители только до $\sqrt{n}$: 
если ни один из них не делит число, оно гарантированно простое. Это снижает сложность проверки с $O(n)$ до $O(\sqrt{n})$, что даёт 
значительный выигрыш в скорости на больших числах.

*Псевдокод определения простоты числа:*
```
Функция is_prime(n):
    1. Присвоить флаг is_composite = 0  // 0 означает "простое", 1 — "составное"

    2. Для каждого делителя d от 2 до ⌊√i⌋ включительно:
       Если is_composite == 0 И (i делится на d без остатка):
           Присвоить is_composite = 1
           Прервать цикл (break)

    3. Если i <= 1:
       Присвоить is_composite = 1  // 0 и 1 не являются простыми числами

    4. Если is_composite == 0:
       Число простое
```

### Практическое расширение
Для оценки эффективности алгоритмов был проведен эксперимент на массивах рандомных чисел размером 10, 100 и 1000 элементов. 
Для бинарного поиска массивы предварительно сортировались алгоритмом сортировки выбором. В качестве искомого элемента выбирался случайный элемент из массива.

| размер массива | линейный поиск | бинарный поиск |
|----------------|----------------|----------------|
| 10             | 10             | 4              |
| 100            | 96             | 7              |
| 1000           | 399            | 7              |

*Псевдокод алгоритма бинарного поиска*
```
1. Присвоить left = 0  // левая граница диапазона поиска
2. Присвоить right = длина(arr) - 1  // правая граница диапазона поиска

3. Пока left ≤ right:
       Вычислить mid = (left + right) // 2  // индекс середины диапазона
       
       Если arr[mid] == target:
           Вернуть mid  // элемент найден, возвращаем его индекс
       
       Если arr[mid] < target:
           Присвоить left = mid + 1  // искомое число больше, сдвигаем левую границу
       Иначе:
           Присвоить right = mid - 1  // искомое число меньше, сдвигаем правую границу

4. Вернуть -1  // цикл завершился, элемент в списке отсутствует
```


## Задание 3. Коллекции и выбор структуры данных
1. Множество подходит для хранения уникальных значений, потому что множество реализовано на хеш-таблице: при добавлении элемента 
автоматически проверяется его наличие за O(1), дубликаты отбрасываются. Это даёт и уникальность, и быстрый поиск.
2. Кортеж можно использовать как ключ словаря, потому что кортеж из неизменяемых элементов (строк, чисел) сам является неизменяемым 
объектом, поэтому у него есть стабильный хеш — главное требование для ключа словаря.
3. Список нельзя использовать как ключ словаря, потому что он является изменяемым объектом и не сможет обеспечить стабильный хеш.
4. Словарь предпочтительнее списка для частого поиска результата по составному ключу, потому что поиск в словаре по ключу-кортежу 
выполняется за O(1) в среднем, тогда как линейный поиск в списке пар — за O(n). При большом числе записей разница критична.

*Оценка средней сложности добавления и поиска для использованных коллекций*

| Структура               | Добавление | Поиск по ключу          | Поиск по значению  |
|-------------------------|------------|-------------------------|--------------------|
| `set` (множество)       | `O(1)`     | `O(1)`                  | `O(n)`             |
| `dict` (словарь)        | `O(1)`     | `O(1)`                  | `O(n)`             |
| `list` (список, append) | `O(1)`     | `O(n)` (линейный поиск) | `O(n)`             |

## Задание 4. Функции, параметры и области видимости
### Исследование LEGB
```
┌─────────────────────────────────────────────────────┐  
│ BUILT-IN (B)                                        │  
│   print, len, range, type, ...                      │  
│  ┌───────────────────────────────────────────────┐  │  
│  │ GLOBAL (G)                                    │  │  
│  │   course = "Python"                           │  │  
│  │   outer, add_result_broken, ...               │  │  
│  │  ┌─────────────────────────────────────────┐  │  │  
│  │  │ ENCLOSING (E) — outer()                 │  │  │  
│  │  │   course = "основы программирования"    │  │  │  
│  │  │  ┌───────────────────────────────────┐  │  │  │  
│  │  │  │ LOCAL (L) — inner()               │  │  │  │  
│  │  │  │   nonlocal course                 │  │  │  │  
│  │  │  │   course = "питон"                │  │  │  │  
│  │  │  └───────────────────────────────────┘  │  │  │  
│  │  └─────────────────────────────────────────┘  │  │  
│  └───────────────────────────────────────────────┘  │  
└─────────────────────────────────────────────────────┘  
```
LEGB — это правило, по которому Python ищет имена переменных:
- L (Local) — локальная область (внутри текущей функции);
- E (Enclosing) — объемлющая область (внешняя функция);
- G (Global) — глобальная область (модуль);
- B (Built-in) — встроенные имена (print, len, range).

Python ищет имя сверху вниз (L -> E -> G -> B) и останавливается на первом найденном.

### Ошибка изменяемого значения по умолчанию
Проблема: значение по умолчанию вычисляется один раз — в момент определения функции (при загрузке модуля), а не при каждом вызове.

**Жизненный цикл объекта:**
1. При компиляции функции создаётся один объект-список [] и сохраняется в атрибуте add_result_broken.__defaults__.
2. При каждом вызове без аргумента results в параметр подставляется ссылка на этот же самый список. 
3. append() мутирует список, и изменения «видны» при следующем вызове.

Исправление: использовать None как «сигнальное» значение по умолчанию и создавать новый список внутри функции.

### Практическое расширение
Две независимые проверки с разными порогами показали, что в замыкании сохраняется значение переменной threshold из 
объемлющей функции на момент её вызова.
