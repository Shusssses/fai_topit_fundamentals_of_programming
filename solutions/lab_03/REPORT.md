## Задание 2. Циклы и базовые алгоритмические схемы
*Временная сложность:*
- вычисление суммы: O(n) - линейно один раз проходимся по последовательности (n - количество элементов);
- поиск минимального значения: O(n) - линейно один раз проходимся по последовательности (n - количество элементов);
- поиск максимального значения: O(n) - линейно один раз проходимся по последовательности (n - количество элементов);
- подсчет четных значений:  O(n) - линейно один раз проходимся по последовательности (n - количество элементов);
- подсчет значений, превосходящих среднее арифметическое: O(2n) в асимптотике упрощается до O(n) - дважды линейно проходимся по массиву (n - количество элементов);
- линейный поиск первого вхождения числа: O(n) - линейно идем по массиву, пока не встретим искомое число (n - количество элементов, стоящих перед искомым +1; в худшем случае - длина массива);
- проверка простоты положительного целого числа: O(n*sqrt(m)) - запускаем цикл с sqrt(m) повторениями (n - количество элементов  массива; m - проверяемое число).

Дополнительная память для каждой операции константа - O(1), т.к. добавляем только новые числовые переменные. 

Если число $n$ составное, то его можно представить как $n = a \cdot b$, где хотя бы один из множителей не превосходит $\sqrt{n}$ — 
иначе их произведение было бы строго больше $n$, что невозможно. Следовательно, достаточно перебирать делители только до $\sqrt{n}$: 
если ни один из них не делит число, оно гарантированно простое. Это снижает сложность проверки с $O(n)$ до $O(\sqrt{n})$, что даёт 
значительный выигрыш в скорости на больших числах.
